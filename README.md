# HarkynB Production

A directly coded, responsive website for HarkynB Production and its four connected brands. Static HTML is generated by a small Node.js script, with no runtime framework, dependency installation, database, or subscription required to run the site.

## Run locally

Requires Node.js 22 or later.

```sh
npm run build
npm test
npm run preview
```

Open http://127.0.0.1:4173. Build output is `dist/`. Never run the build concurrently with another build.

## Deploy on Cloudflare Pages

In Cloudflare, select **Workers & Pages > Create application > Pages > Import an existing Git repository**. Choose this repository and use:

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Framework preset | None |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | Leave blank |
| Node version | `22` (set `NODE_VERSION=22` if needed) |

No secret or API key is required. Keep the review version behind Cloudflare Access if it should be private. `noindex` is an indexing request, not access protection.

For **Workers Builds** instead of Pages: build with `npm run build`, deploy with `npx wrangler deploy`. The supplied `wrangler.jsonc` serves `dist` as static assets and uses the generated `404.html`. The Pages route above is the simplest Git-connected setup for this project.

Official references: [Pages Git integration](https://developers.cloudflare.com/pages/get-started/git-integration/) and [Workers static assets](https://developers.cloudflare.com/workers/static-assets/).

## Pages and interactions

- Parent: Home, About, Services, Work, Brands, Impact, News, Contact, Privacy, Website/Booking Information.
- Dedicated brands: Onevoicefm, HarkynBShotIt, HarkynB Creators Academy, Future Creators Summit.
- Academy: six individual course direction pages, institutional training, and sponsorship.
- Summit: Summit 1.0 archive, gallery categories, speaker directory support, video archive support, partnerships, and next-edition configuration.
- Mobile menu, native form validation, preselected team/service enquiries, downloadable drafts, category filters, keyboard-accessible image lightbox, live stream error state, and reduced motion support.
- Configured projects receive their own generated detail pages.

## Content editing

The repository is the content source. Edit `content/settings.json` for contacts, media, portfolio projects, news, audio, and speaker information. Edit `content/catalogue.mjs` for brand, service, and course descriptions. Longer page copy is in `scripts/build.mjs`, `scripts/brand-pages.mjs`, and `scripts/contact-pages.mjs`.

This is file-based editing through GitHub, not a visual CMS or admin dashboard. A visual CMS and automatic enquiry inbox are future integrations, not included functionality.

Use the schema and examples in [CONTENT_GUIDE.md](CONTENT_GUIDE.md). Put approved images in `public/media/` and refer to them as `/media/filename.webp`. Build again after changing content. Public files and `settings.json` are visible to visitors; never put credentials or private records in them.

## Enquiries

This version does **not** automatically submit forms. It creates a text draft for download. After verified per-team email/WhatsApp contacts are configured, visitors can open a draft in their email or WhatsApp app, review it, and send it themselves. No request is falsely marked as sent.

No form data is stored in localStorage, cookies, or a database. Forms require JavaScript. If automatic collection is needed, add a Cloudflare Worker/Pages Function with appropriate validation, spam controls, consent wording, and a confirmed delivery destination.

## Readiness before public launch

- Replace the text wordmark with approved logos, if desired.
- Upload actual company portfolio photographs, authorised student work, and Summit 1.0 media. No stock images or invented work are presented as company projects.
- Confirm the service scope, brand details, all programme information, Summit date, speaker profiles, and permissions.
- Configure verified contact routing, social accounts, and the real audio stream. No fake programmes, audio, prices, course dates, or impact metrics are supplied.
- Add the public origin to `siteUrl`, review the privacy/booking information, and set `reviewMode` to `false` when ready. This removes the review notice and noindex directives. A sitemap is generated when `siteUrl` is set.
- Test the deployed site on mobile, test enquiry drafts with the configured contact apps, and verify the radio stream on the actual host.

## Design and assets

The temporary visual identity uses charcoal, ivory, orange, and an original CSS production-frame composition. Each brand has a related but distinct palette. Google Fonts provides DM Sans and Manrope with local Arial fallbacks. Loading fonts makes requests to Google; self-host approved font files if required by the final privacy approach.

Security headers are in `public/_headers`. The content security policy permits self-hosted scripts, Google font styles/fonts, HTTPS images/media, and no embedded frames. Update this deliberately if adding other integrations.

`npm test` checks generated pages, local links/assets and anchors, required metadata, route coverage, and form structure. It does not substitute for real-device or deployed browser testing.
